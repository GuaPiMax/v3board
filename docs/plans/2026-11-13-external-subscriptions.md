# 第三方订阅聚合实施计划

**Goal:** 在不改变本站原有节点行为的前提下，按套餐下发第三方节点。

**Architecture:** 独立订阅来源、套餐关联表、加密节点快照和后台管理页。定时任务负责安全拉取；用户请求只读取有效快照。第三方凭据不进入用户网页节点接口，不使用本站 UUID 替换第三方凭据。

**Tech Stack:** PHP 8.4、Laravel 8、现有数据库与缓存、PHP cURL、原生 HTML/JavaScript。

## 已确认的业务规则

- 来源和套餐多对多；以用户当前 plan_id 为准。
- 未封禁、未到期且本站剩余流量大于零时下发第三方节点。
- 本站流量用尽停止下发，重置或加购恢复额度后恢复。
- 第三方流量不统计；已下载的共享第三方凭据无法由本站撤销。
- 每 30 分钟刷新，失败保留最近成功快照至成功时间后 24 小时。
- 支持管理员手动刷新、停用、编辑、删除及绑定套餐。
- 输入为普通或 Base64 URI 列表；解析 SS、VMess、VLESS、Trojan、Hysteria 2、TUIC、AnyTLS。
- 按仓库现有客户端逐项适配；不能完整转换的节点跳过并诊断。
- 独立管理页完整源码放在本仓库，不直接修改后台压缩 JS。
- 用户要求完成测试、安全检查后推送至其 fork。

## 实施顺序

1. 检查全部输出生成器，建立协议及参数兼容矩阵；准备 PHP 8.4、Composer 与隔离测试数据库。
2. 实现独立 URI 解析器：严格解析、输入长度限制、凭据保留、格式错误诊断，先编写七种协议及恶意输入测试。
3. 实现安全下载器：HTTPS/HTTP URL 校验、公网地址限制、DNS 解析与连接绑定、重定向逐跳校验、超时与大小上限、TLS 校验；不记录 URL 或响应正文。
4. 添加独立数据表和可重复执行的安装入口；实现多对多绑定、加密存储、原子快照更新、防并发覆盖与过期策略。
5. 实现管理员 API 和独立管理界面；沿用管理员鉴权，避免原有请求日志泄漏订阅令牌；普通用户不得读取来源凭据。
6. 将快照接入订阅输出和网页节点列表：只通过明确接入点修改上游文件；分别处理用户可见元数据与含凭据的订阅配置。
7. 逐项验证现有客户端输出，特别检查 TUIC 独立 UUID/密码、SS 2022、TLS、Reality、WS/gRPC、名称转义和不支持参数。
8. 验证账户到期/封禁/流量耗尽、套餐变更、多对多绑定、缓存过期、同步失败、未安装/未启用功能时的原有行为。
9. 安全审查、依赖审计、PHP 语法检查、运行集成测试与管理页检查；修复发现的问题。
10. 编写安装、定时任务、回滚、上游合并与回归说明；检查 git diff 后提交并推送。

## 维护边界

保留独立命名空间、路由文件、迁移和页面源码。上游合并必须运行第三方功能回归；不能保证任意未来上游变更零冲突。服务器 update.sh 强制同步 origin/master，因此部署远程必须指向用户 fork，且功能提交必须保留在该分支中。

## 当前状态

业务需求已确认，功能实现与本地 PHP 8.4 测试完成。用户选择保留原有框架并单独报告依赖风险。安全拉取采用禁止重定向、由管理员填写最终 URL 的方式；维护文档与检查结果分别见 docs/external-subscriptions.md、docs/external-subscriptions-review.md。提交与推送状态以 Git 历史为准。
